# انتشار سایت از مخزن

`/site` منبع حقیقت سایت tajrobeh.life است. هر تغییر سایت یک PR است و مرجش روی `main` یعنی انتشار زنده.

## اجرا

همهٔ کارهایی که به سایت می‌رسند روی GitHub Actions اجرا می‌شوند (محیط Claude به سرور ایرانی سایت نمی‌رسد).
رمز فقط `WP_USER` و `WP_APP_PASSWORD` (کاربر claude-ops) در GitHub Secrets. `WP_BOT_*` مال بات است و اینجا به کار نمی‌رود.
روی دستگاه: فایل `~/.config/tajrobeh/site.env` یا `.env` ریشهٔ مخزن (در `.gitignore`) با همین دو نام.

| گردش کار | کی | چه می‌کند |
|---|---|---|
| `site-check.yml` | هر PR روی `/site` | نحو PHP و JSON، خط تیره، رمز در خط‌های تازه؛ برنامهٔ انتشار و ناهمخوانی با سایت زنده |
| `site-deploy.yml` | مرج روی `main` | برنامه ← برگهٔ آزمایشی خصوصی ← انتشار ← تست دود ← پاک کردن کش ← ۱۵ دقیقه نظارت ← برگشت خودکار |
| `site-pull.yml` | دستی | وضعیت زنده را می‌خواند و روی شاخهٔ `site-sync/live` می‌گذارد (برای PR همگام‌سازی) |
| `site-audit.yml` | دستی | Lighthouse، امنیت، لید، لینک‌ها. ثبت آزمایشی فرم ۷ فقط با `lead_submit=1` |
| `site-weekly.yml` | شنبه ۶:۴۵ تهران | چک هفتگی و گزارش کوتاه |

ابزارها در `site/tools/` هستند، نه `.github/scripts/` (تغییر آنجا انتشار بات را راه می‌اندازد).

## قاعدهٔ انتشار هر شیء

- نسخهٔ زنده = نسخهٔ تازهٔ مخزن: کاری نیست.
- نسخهٔ زنده = نسخهٔ قبلی مخزن: منتشر می‌شود.
- هیچ‌کدام: کسی در وردپرس دستی عوضش کرده. منتشر نمی‌شود و گردش کار قرمز می‌شود؛ اول `site-pull` و PR همگام‌سازی.
- **برگه:** اول روی کپی خصوصی `tj-staging-<id>` رندر و سنجیده می‌شود، بعد برگهٔ اصلی. کپی پاک می‌شود.
- **اسنیپت موجود:** متن کد عوض می‌شود و فوراً تست دود؛ اگر مردود بود، نسخهٔ قبلی برمی‌گردد.
- **اسنیپت تازه:** غیرفعال ساخته می‌شود، روشن می‌شود، تست دود فوری، و اگر مردود بود در کمتر از یک دقیقه خاموش می‌شود. شناسه‌اش خودکار در `snippets/index.json` نوشته می‌شود. در index.json با `"id": null` و `type` و `loc` (یکی از `everywhere`، `frontend_only`، `site_wide_header`، `site_wide_footer`) اضافه کن.
- **روشن/خاموش اسنیپت:** با عوض کردن `active` در `snippets/index.json`.
- **برگهٔ 503886 (مینی‌اپ)** با گردش کار بات منتشر می‌شود و **پل tj-ops** فقط دستی در WPCode.

تست دود: ۶ صفحهٔ اصلی و برگه‌های عوض‌شده (۲۰۰، بی خطای PHP، حجم دست‌کم نصف قبل)، حضور فرم‌های لید، `tj/v1/thers`، همهٔ ریدایرکت‌های `site/redirects.json`، و زمان پاسخ خانه (بیشتر از دو برابر و ۸۰۰ms = مردود).

## پل tj-ops

`site/snippets/ops-bridge.php`. اسنیپت‌های WPCode، متای خام Yoast و کش WP-Optimize راه REST ندارند؛ این پل هفت کنش فهرست‌شده را فقط برای claude-ops با Application Password باز می‌کند.
کلید خاموش: **تنظیمات › عمومی › «پل انتشار مخزن (tj-ops)»**. پیش‌فرض خاموش. هر فراخوانی با زمان، کنش، نتیجه و IP در گزینهٔ `tj_ops_log` ثبت می‌شود.

### نصب (یک بار، Cowork در مرورگر)

1. WPCode › افزودن اسنیپت › «کد سفارشی». عنوان: `Tajrobeh — پل انتشار مخزن (tj-ops)`. نوع: PHP.
2. متن کامل `site/snippets/ops-bridge.php` از شاخهٔ `main` را بچسبان (بی `<?php`).
3. محل اجرا: «اجرا همه جا» (Run Everywhere). ذخیره و فعال.
4. تنظیمات › عمومی › «پل انتشار مخزن (tj-ops)» را روشن کن و ذخیره.
5. شناسهٔ اسنیپت را به Claude Code بگو تا در `snippets/index.json` ثبت شود.

## تست فرم‌های سایت
- هر ثبت آزمایشی فقط با دادهٔ TEST: نام «تست TEST ممیزی»، شمارهٔ ساختگی `09123456789`، ایمیل `@example.invalid` و برچسب `TEST-<شمارهٔ اجرا>`. بات (`isTestLead_`، v170.7) چنین فرمی را در همهٔ مسیرها بی‌صدا کنار می‌گذارد: نه سطر، نه کارت، نه پیام. ورودی فلوئنت را خود ابزار پاک می‌کند. <!-- pii:ok ساختگی -->
- ثبت آزمایشی فقط با اجرای دستی `site-audit.yml` (`lead_submit=1`) و فقط وقتی پیش‌تر اعلام شده باشد. هیچ کار پس‌زمینه یا زنجیره‌ای تست را خودکار و بیرون از برنامهٔ اعلام‌شده اجرا نمی‌کند؛ هر کار پس‌زمینه‌ای که برنامه‌اش عوض شد همان لحظه متوقف می‌شود.

## گزارش

بعد از هر انتشار و هر چک هفتگی یک گزارش کوتاه در خلاصهٔ گردش کار است. وقتی کنش `send` (بات v170.1) منتشر شد و سه secret
`BOT_API_URL`، `BOT_API_KEY` و `REPORT_CHAT_ID` گذاشته شد، همان گزارش از بات برای یاسر می‌رود.
